### กติกาการทำงานของทีม
- ใช้ GitHub เดียว (public) — แตก branch ต่อ feature, เปิด PR, อย่างน้อย 1 คน review ก่อน merge
- ใช้ GitHub Projects (Kanban: Backlog / Doing / Review / Done) ติดตามงาน
- Stand-up สั้น 15 นาที สัปดาห์ละ 2 ครั้ง, ทุกคนต้องมี commit ของตัวเอง (อาจารย์ดูได้จาก contribution graph)
- อนุญาตให้ใช้ AI agent ช่วยเขียนโค้ด — ระบุใน README ว่าส่วนไหนใช้ AI ช่วย

## 2. Domain ที่เลือก

**ธุรกิจขนส่งและโลจิสติกส์ขนาดกลาง (SME Logistics / Fleet Operator)**
ตัวอย่างบริษัทสมมติ: *"สยามฟลีท ทรานสปอร์ต"* — รถบรรทุก 40 คัน, พนักงานขับรถ 55 คน (มีแรงงานต่างด้าว ~15 คน)

### ทำไมเลือก domain นี้
- เอกสารที่ "มีวันหมดอายุ" เยอะมาก และ **ผูกกับกฎหมาย** — หมดอายุ = วิ่งรถไม่ได้ / โดนปรับ / ประกันไม่คุ้มครอง
- เอกสารมาหลายรูปแบบ: บัตรพลาสติก, กระดาษสแกน, ถ่ายรูปจากมือถือ, PDF จากหน่วยงาน — เหมาะกับ Document Intelligence
- ใช้ปี **พ.ศ.** ผสม ค.ศ. และภาษาไทยผสมอังกฤษ — ความท้าทายทาง AI ที่ชัดเจน

### ประเภทเอกสารที่ระบบรองรับ (MVP)

| กลุ่ม | เอกสาร | ผูกกับ | รอบต่ออายุโดยทั่วไป |
|------|--------|-------|-------------------|
| คนขับ | ใบอนุญาตขับรถ (ท.2 / ท.3) | พนักงาน | 3–5 ปี |
| คนขับ | Work Permit / Visa (แรงงานต่างด้าว) | พนักงาน | 1–2 ปี |
| รถ | ภาษีรถประจำปี (ป้ายวงกลม) | รถ | 1 ปี |
| รถ | พ.ร.บ. คุ้มครองผู้ประสบภัยจากรถ | รถ | 1 ปี |
| รถ | กรมธรรม์ประกันภัยรถยนต์ / ประกันสินค้า | รถ | 1 ปี |
| บริษัท | ใบอนุญาตประกอบการขนส่ง | บริษัท | 5–7 ปี |
| บริษัท | สัญญาจ้างขนส่งกับลูกค้า | ลูกค้า | ตามสัญญา |

## 3. Pain Point ในกระบวนการ

**กระบวนการที่เลือก: "การติดตามและต่ออายุเอกสารที่มีวันหมดอายุ" ของฝ่ายธุรการ/บุคคล**

### กระบวนการปัจจุบัน (As-Is)
1. เอกสารเข้ามาทาง LINE, อีเมล, กระดาษ → เก็บในแฟ้ม/Google Drive แบบกระจัดกระจาย
2. ธุรการ **พิมพ์วันหมดอายุลง Excel ด้วยมือ** (บางครั้งพิมพ์ผิด พ.ศ./ค.ศ.)
3. ต้อง **เปิด Excel ไล่ดูเอง** ว่าอะไรใกล้หมด — ไม่มีใครเตือน
4. รู้ตัวเมื่อ "หมดไปแล้ว" (ตำรวจเรียก, ลูกค้าขอเอกสาร, เคลมประกันไม่ได้)

### ผลกระทบ (สมมติฐานที่ทีมต้องยืนยันด้วยการสัมภาษณ์/อ้างอิง)
| ปัญหา | ผลกระทบ |
|-------|---------|
| ป้อนข้อมูลด้วยมือ ~5–10 นาที/เอกสาร | ธุรการเสียเวลาหลายชั่วโมง/เดือน |
| พิมพ์ปีผิด (พ.ศ.↔ค.ศ.) | ระบบเตือนผิด หรือไม่เตือนเลย |
| ไม่มีระบบเตือนล่วงหน้า | ค่าปรับ, รถจอดวิ่งไม่ได้, เสียงานลูกค้า |
| พ.ร.บ./ประกันขาด | ความเสี่ยงทางการเงินสูงมากเมื่อเกิดอุบัติเหตุ |
| ข้อมูลกระจัดกระจาย | ตอบคำถามง่าย ๆ ไม่ได้ เช่น "เดือนหน้ามีอะไรต้องต่อบ้าง?" |

### Problem Statement
> ฝ่ายธุรการของบริษัทขนส่ง SME ต้องติดตามเอกสารหลายร้อยฉบับที่มีวันหมดอายุด้วยการพิมพ์ลง Excel และเปิดตรวจเอง ทำให้เสียเวลาและเกิดเอกสารหมดอายุโดยไม่รู้ตัว ส่งผลให้ถูกปรับ เสียงาน และมีความเสี่ยงทางกฎหมาย

### User Stories
- **US1** ในฐานะธุรการ ฉันอยากอัปโหลดรูป/PDF เอกสาร แล้วระบบ **ดึงข้อมูลและวันหมดอายุให้อัตโนมัติ** เพื่อไม่ต้องพิมพ์เอง
- **US2** ในฐานะธุรการ ฉันอยาก **ตรวจทานและแก้ไข** ค่าที่ AI ไม่มั่นใจ ก่อนบันทึกจริง
- **US3** ในฐานะผู้จัดการ ฉันอยากได้ **แจ้งเตือนล่วงหน้า 90/60/30/7 วัน** ผ่าน LINE/อีเมล
- **US4** ในฐานะผู้จัดการ ฉันอยาก **ถามเป็นภาษาธรรมชาติ** เช่น "รถทะเบียน 70-1234 มีอะไรใกล้หมดบ้าง"
- **US5** ในฐานะผู้จัดการ ฉันอยากเห็น **Dashboard** สถานะเอกสารทั้งหมด (ปกติ / ใกล้หมด / หมดแล้ว)

### Success Criteria (ตัววัดความสำเร็จ)
- ดึง **วันหมดอายุถูกต้อง ≥ 90%** บนชุดทดสอบ
- ดึงฟิลด์หลัก (ประเภทเอกสาร, เลขที่, ชื่อผู้ถือ/ทะเบียนรถ) ถูกต้อง ≥ 85%
- ลดเวลาบันทึกเอกสารจาก ~5 นาที เหลือ < 1 นาที (รวมเวลาตรวจทาน)
- ไม่มีเอกสารที่หมดอายุโดยไม่ถูกแจ้งเตือนล่วงหน้า (0 missed alerts ในการจำลอง)
