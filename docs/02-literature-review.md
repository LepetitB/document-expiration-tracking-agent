# 02 — Literature Review: โซลูชันที่มีอยู่แล้ว

บทนี้ดูว่าปัญหา *"ติดตามวันหมดอายุภาษีรถ / พ.ร.บ. / ประกันภัย ของรถทั้งบริษัท"* ปัจจุบันแก้กันด้วยอะไรบ้าง แต่ละทางมีข้อดีข้อเสียอย่างไร และทางไหนเหมาะกับ **บริบทและข้อจำกัดของโปรเจคเรา**

## 1. เกณฑ์เปรียบเทียบ (มาจาก context + constraints)

| # | เกณฑ์ | ทำไมสำคัญ |
|---|------|----------|
| C1 | **อ่านเอกสารให้อัตโนมัติ** | root cause #1–3: ข้อมูลติดในรูป, พิมพ์ผิด, หลายวันที่ |
| C2 | **รองรับภาษาไทย / ปี พ.ศ. / หลายบริษัทประกัน** | เอกสารรถไทยมีหลายรูปแบบ |
| C3 | **ดูภาพรวมทั้งกองรถ** (รายคัน) | ต้องรู้ว่าคันไหนวิ่งได้ |
| C4 | **แจ้งเตือนเชิงรุกหลายรอบ** | กันการลืม |
| C5 | **ต้นทุนเหมาะกับ SME** | ไม่มีงบระบบใหญ่ |
| C6 | **ติดตั้งและใช้ง่าย** | ไม่มีทีม IT |
| C7 | **ความเป็นส่วนตัวของข้อมูล** | เอกสารมีข้อมูลบริษัท |
| C8 | **ทำได้จริงใน ~4 สัปดาห์** | ข้อจำกัดของรายวิชา |

## 2. โซลูชันที่มีอยู่

### 2.1 Excel / Google Sheets + ปฏิทิน (สิ่งที่ SME ใช้อยู่)
- **ข้อดี:** ฟรี, ทุกคนใช้เป็น, ทำสีแดงเมื่อใกล้หมดได้
- **ข้อเสีย:**
  - พิมพ์เองทั้งหมด
  - พิมพ์ พ.ศ./ค.ศ. ผิดได้
  - ไม่เตือนเอง
  - เอกสารจริงแยกอยู่อีกที่
  - ข้อมูลอยู่กับคนคนเดียว
- **สรุป:** เป็น baseline ที่ทำให้เกิดปัญหาตั้งแต่แรก

### 2.2 การแจ้งเตือนจากบริษัทประกัน / นายหน้า / ช่องทางต่อภาษีออนไลน์
- **ข้อดี:**
  - บริษัทประกันหรือนายหน้ามักโทรหรือส่ง SMS เตือนก่อนครบรอบ
  - มีช่องทางชำระภาษีรถออนไลน์ที่ช่วยให้ "ต่อ" สะดวกขึ้น
- **ข้อเสีย:**
  - แต่ละเจ้าเตือนเฉพาะกรมธรรม์ของตัวเอง
  - รถ 40 คันที่ทำประกันหลายเจ้าจึง **ไม่มีภาพรวมที่เดียว**
  - การเตือนไปที่เบอร์ของคนที่ทำประกัน ซึ่งอาจลาออกไปแล้ว
  - ไม่บอกว่าคันไหน "ห้ามวิ่ง"
- **สรุป:** ช่วยได้บางส่วน แต่ควบคุมไม่ได้ และไม่ครบ (ไม่ผ่าน C3)

### 2.3 แอปเตือนความจำทั่วไป (Google Calendar, LINE reminder, Notion)
- **ข้อดี:** ฟรี, เตือนบนมือถือได้
- **ข้อเสีย:** ยังต้องพิมพ์เอง, ไม่มีโครงสร้างข้อมูลรายคัน, สรุปไม่ได้
- **สรุป:** แก้ได้แค่ C4

### 2.4 ซอฟต์แวร์บริหารกองรถ (Fleet Management) เช่น Fleetio และระบบ GPS fleet ในไทย
- **ข้อดี:**
  - ผูกข้อมูลกับรถแต่ละคัน
  - มีระบบเตือนต่อทะเบียน/ประกัน [[Fleetio]](https://www.fleetio.com/blog/automating-vehicle-renewals-and-fleet-registration-reminders)
  - รวมงานซ่อมบำรุง
- **ข้อเสีย:**
  - คิดเงินรายคันรายเดือน เว็บรีวิวภายนอกระบุราว $3–4/คัน/เดือน ซึ่งไม่ตรงกันระหว่างแหล่ง [[Capterra]](https://capterra.com/p/120855/Fleetio/), [[B2B Reviews]](https://www.b2breviews.com/?p=1281)
  - ส่วนใหญ่ **ยังต้องกรอกวันหมดอายุเอง**
  - ภาษาอังกฤษ ไม่เข้าใจปี พ.ศ.
  - ระบบ GPS ไทยเน้นติดตามตำแหน่งรถมากกว่าเอกสาร
- **สรุป:** ใกล้เคียงที่สุดด้าน C3–C4 แต่ไม่ผ่าน C1–C2 และแพงสำหรับ SME

### 2.5 ระบบเก็บเอกสาร (Google Drive / SharePoint)
- **ข้อดี:** เก็บไฟล์รวมศูนย์, แชร์ได้
- **ข้อเสีย:** ไม่อ่านเนื้อหาว่าหมดอายุเมื่อไร และไม่เตือน
- **สรุป:** แก้แค่ "ไฟล์กระจัดกระจาย"

### 2.6 Cloud Document AI / OCR: Azure AI Document Intelligence, Google Document AI, AWS Textract
- **ข้อดี:** OCR แม่นยำ, สร้าง custom model ได้, คิดเงินต่อหน้า
- **ข้อเสีย:**
  - ต้อง **เทรน custom model ทีละแบบฟอร์ม** (กรมธรรม์แต่ละบริษัทประกันหน้าตาต่างกัน)
  - การรองรับภาษาไทยของ custom extraction ยังไม่ชัดเจน
  - custom extraction แพงกว่า OCR ธรรมดาหลายเท่า: ~$1.5 เทียบกับ ~$30 ต่อ 1,000 หน้า ตามที่ [ERPResearch](https://erpresearch.com/erp-add-ons/ocr/azure-document-intelligence/pricing) อ้าง (เป็นตัวเลขจากบุคคลที่สาม)
  - ได้แค่ข้อความ ยังต้องสร้างระบบติดตามเอง
- **สรุป:** ผ่าน C1 บางส่วน แต่ setup หนัก

### 2.7 OCR ภาษาไทยเฉพาะทาง (เช่น iApp Technology)
- **ข้อดี:**
  - เก่งภาษาไทย เช่น OCR บัตรประชาชน อ้างความแม่นยำระดับตัวอักษร ~98% [[iApp]](https://www.iapp.co.th/docs/ekyc/thai-national-id-card)
  - มี OCR เอกสารทั่วไป [[iApp Docs]](https://iapp.co.th/blog/iapp-4-new-document-ocr)
- **ข้อเสีย:**
  - ไม่พบโมเดลสำเร็จรูปสำหรับป้ายภาษี พ.ร.บ. หรือกรมธรรม์
  - OCR ทั่วไปได้แค่ข้อความดิบ ต้องเขียนกฎแยกฟิลด์เอง
  - ไม่มีระบบติดตาม
- **สรุป:** ผ่าน C2 แต่ไม่ผ่าน C1 (การแยกฟิลด์) และ C3

### 2.8 Vision Large Language Models (Claude, GPT, Gemini)
- **ข้อดี:**
  - อ่านรูปหรือ PDF ภาษาไทยได้ **โดยไม่ต้องเทรน**
  - แยกได้ว่าวันไหนคือวันหมดอายุ
  - อ่านทะเบียนรถได้
  - ส่งผลเป็น JSON ตาม schema
  - ใช้ทำ Agent ตอบคำถามได้
- **ข้อเสีย:**
  - อาจ "มั่นใจแต่ผิด"
  - มีค่าใช้จ่ายต่อครั้ง
  - ข้อมูลถูกส่งไปผู้ให้บริการ
  - คำนวณวันที่อาจพลาด
- **สรุป:** ผ่าน C1–C2 ดีที่สุด **ถ้าออกแบบกลไกกันผิดพลาด**

**ช่องว่างที่พบ:**
- ระบบที่ **ดูภาพรวมรถและเตือนได้** (Fleet Management) ยังต้องพิมพ์ข้อมูลเองและไม่รองรับภาษาไทย
- ระบบที่ **อ่านเอกสารได้** (OCR / Document AI) ก็ไม่รู้จัก "รถ" และไม่มีระบบเตือน
- **ยังไม่มีตัวเลือกไหนที่ทำได้ครบในราคา SME**

## 4. ทางเลือกของเรา และเหตุผล

**เลือก: Vision LLM อ่านเอกสาร → กฎตรวจสอบ → คนตรวจเมื่อไม่มั่นใจ → Dashboard สถานะรายคัน + แจ้งเตือน + Agent**

| เหตุผล | อธิบาย |
|-------|-------|
| ปิดช่องว่าง C1–C4 ในระบบเดียว | AI อ่านเอกสาร ระบบเราดูแลภาพรวมรายคันและการเตือน |
| ไม่ต้องเทรนต่อบริษัทประกัน | กรมธรรม์เจ้าใหม่หรือภาษาอังกฤษก็อ่านได้ ทดสอบแล้วในชุด eval |
| ลดจุดอ่อนของ LLM ด้วยการออกแบบ | ให้ AI คัดลอกวันที่ดิบ แล้ว **แปลง พ.ศ. ด้วยโค้ด** + กฎตรวจทะเบียนรถและลำดับวันที่ + confidence ต่ำส่งให้คนตรวจ + Agent ตอบจากฐานข้อมูลจริง |
| ต้นทุนต่ำ | ~120 ฉบับต่อปี จ่ายตามการใช้งาน ไม่มีค่า license รายคัน |
| มี baseline เปรียบเทียบ | ระบบกฎ (regex) ใช้ได้ออฟไลน์ และใช้เทียบผล |
| ทำทันเวลา | ไม่ต้องเทรนโมเดล |

**ข้อจำกัดที่ยอมรับ:**
- ต้องส่งรูปเอกสารไปประมวลผลภายนอก (ใน repo ใช้ข้อมูลสมมติเท่านั้น)
- ต้องใช้อินเทอร์เน็ตและ API key (มีโหมดออฟไลน์สำรอง)
