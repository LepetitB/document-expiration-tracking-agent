# 02 — Literature Review: โซลูชันที่มีอยู่แล้วในตลาด

เป้าหมายของบทนี้คือดูว่าปัญหา *"ติดตามเอกสารที่มีวันหมดอายุ"* ปัจจุบันแก้กันด้วยอะไรบ้าง แต่ละทางมีข้อดีข้อเสียอย่างไร และทางไหนเหมาะกับ **บริบทและข้อจำกัดของโปรเจคเรา**

## 1. เกณฑ์ที่ใช้เปรียบเทียบ (มาจาก context + constraints)

| # | เกณฑ์ | ทำไมสำคัญกับโจทย์นี้ |
|---|------|------------------|
| C1 | **อ่านเอกสารให้อัตโนมัติ** (ไม่ต้องพิมพ์เอง) | เป็นต้นเหตุอันดับ 1–3 ใน Rationale |
| C2 | **รองรับภาษาไทยและปี พ.ศ.** | เอกสารส่วนใหญ่เป็นของหน่วยงานไทย |
| C3 | **ครอบคลุมทุกประเภท**: คน + รถ + บริษัท + สัญญา | SME ไม่อยากใช้ 3 ระบบแยกกัน |
| C4 | **แจ้งเตือนเชิงรุก** หลายรอบ | กันการพลาดเพราะลืมเปิดดู |
| C5 | **ต้นทุนเหมาะกับ SME** | ไม่มีงบระบบระดับองค์กร |
| C6 | **ติดตั้งง่าย / ใช้ได้ภายในไม่กี่วัน** | ไม่มีทีม IT |
| C7 | **ความเป็นส่วนตัว (PDPA)** | มีข้อมูลบุคคล เช่น เลขใบขับขี่ และพาสปอร์ต |
| C8 | **ทำได้จริงในเวลาโปรเจค (~4 สัปดาห์)** | ข้อจำกัดของรายวิชา |

## 2. โซลูชันที่มีอยู่

### 2.1 Excel / Google Sheets + ปฏิทิน (สิ่งที่ SME ใช้อยู่)
- **ข้อดี:** ฟรี, ทุกคนใช้เป็น, ยืดหยุ่น, ใช้ conditional formatting ทำสีแดงเมื่อใกล้หมดได้
- **ข้อเสีย:**
  - ต้องพิมพ์ข้อมูลเองทั้งหมด (ไม่ผ่าน C1)
  - พิมพ์ พ.ศ./ค.ศ. ผิดได้
  - ไม่เตือนเองถ้าไม่เขียน script เพิ่ม
  - ไฟล์เอกสารจริงแยกอยู่อีกที่
  - ข้อมูลอยู่กับคนคนเดียว
- **สรุป:** เป็น baseline ที่ทำให้เกิดปัญหาตั้งแต่แรก

### 2.2 แอปเตือนความจำทั่วไป (Google Calendar, LINE reminder bot, Notion)
- **ข้อดี:** ฟรีหรือถูก, เตือนผ่านมือถือได้
- **ข้อเสีย:**
  - ยังต้องพิมพ์ข้อมูลเอง
  - ไม่มีโครงสร้างข้อมูล (ใคร/รถคันไหน/เลขที่)
  - สรุปภาพรวมหรือค้นหาไม่ได้
  - ไม่ผูกกับไฟล์เอกสาร
- **สรุป:** แก้แค่ C4 ข้อเดียว

### 2.3 ซอฟต์แวร์บริหารกองรถ (Fleet Management) เช่น Fleetio และระบบ GPS fleet ในไทย
- **ข้อดี:**
  - มี reminder สำหรับต่อทะเบียน ประกัน และใบขับขี่ ผูกกับรถและคนขับ [[Fleetio blog]](https://www.fleetio.com/blog/automating-vehicle-renewals-and-fleet-registration-reminders), [[Fleetio contacts]](https://fleetio.com/features/contact-management)
  - รวมงานซ่อมบำรุงด้วย
- **ข้อเสีย:**
  - คิดเงินต่อคันต่อเดือน รีวิวจากเว็บภายนอกระบุราว $3–4/คัน/เดือน และราคาไม่ตรงกันระหว่างแหล่ง [[Capterra]](https://capterra.com/p/120855/Fleetio/), [[B2B Reviews]](https://www.b2breviews.com/?p=1281)
  - ส่วนใหญ่ยังต้องกรอกวันหมดอายุเอง
  - เป็นภาษาอังกฤษ ไม่เข้าใจ พ.ศ.
  - ไม่ครอบคลุม Work Permit/Visa หรือสัญญาลูกค้า
  - ระบบ GPS ไทยเน้นติดตามตำแหน่งรถมากกว่าเอกสาร
- **สรุป:** ดีด้าน C4 แต่ไม่ผ่าน C1, C2, C3

### 2.4 ระบบ HR / HRIS
- **ข้อดี:** เก็บเอกสารพนักงาน บางระบบเตือนวันหมดอายุ Work Permit ได้
- **ข้อเสีย:** ไม่ครอบคลุมเอกสารรถหรือสัญญา และส่วนใหญ่ยังต้องกรอกเอง
- **สรุป:** แก้ได้แค่ฝั่ง "คน"

### 2.5 ระบบจัดการเอกสาร (DMS): Google Drive, SharePoint
- **ข้อดี:** เก็บไฟล์รวมศูนย์, ค้นชื่อไฟล์ได้, กำหนดสิทธิ์ได้
- **ข้อเสีย:** ไม่ได้ "อ่าน" เนื้อหาว่าหมดอายุเมื่อไร (metadata ต้องกรอกเอง) และไม่มีตรรกะการแจ้งเตือนตามวันหมดอายุ
- **สรุป:** แก้ปัญหา "ไฟล์กระจัดกระจาย" แต่ไม่ใช่ปัญหาหลัก

### 2.6 Contract Lifecycle Management (CLM) ที่ใช้ AI: Sirion, Ironclad, DocuSign CLM ฯลฯ
- **ข้อดี:**
  - ใช้ AI/LLM ดึงวันต่ออายุ เงื่อนไข และ notice period จากสัญญาได้อัตโนมัติ
  - มีระบบเตือนก่อนหมดกำหนด [[Sirion]](https://www.sirion.ai/library/contract-insights/contract-renewal-and-expiration-management-with-ai/)
- **ข้อเสีย:**
  - แพงระดับองค์กร เช่น Ironclad ประเมินที่ $25,000–75,000+ ต่อปี [[Hyperstart]](https://www.hyperstart.com/blog/contract-renewal-management-software/)
  - ออกแบบมาสำหรับสัญญาเท่านั้น ไม่ใช่ใบขับขี่หรือป้ายภาษี
  - ภาษาไทยไม่ใช่จุดเด่น
- **สรุป:** แนวคิด "AI อ่านเอกสาร + เตือน" ตรงกับเรา แต่ราคาและขอบเขตไม่เหมาะกับ SME → **เป็นแรงบันดาลใจ**

### 2.7 Cloud Document AI / OCR APIs: Azure AI Document Intelligence, Google Document AI, AWS Textract
- **ข้อดี:**
  - OCR แม่นยำ
  - มีโมเดลสำเร็จรูป (ใบเสร็จ, บัตรประชาชน)
  - สร้าง custom model ได้
  - คิดเงินตามจำนวนหน้า
- **ข้อเสีย:**
  - ต้อง **เทรน custom model ทีละประเภทเอกสาร** (มีหลายแบบฟอร์มจากหลายบริษัทประกัน)
  - การรองรับภาษาไทยของ custom extraction ยังไม่ชัดเจน
  - ราคา custom extraction สูงกว่า OCR อ่านอย่างเดียวหลายเท่า ([ERPResearch](https://erpresearch.com/erp-add-ons/ocr/azure-document-intelligence/pricing) อ้าง ~$1.5 เทียบกับ ~$30 ต่อ 1,000 หน้า ตัวเลขจากบุคคลที่สาม)
  - ได้แค่ "ข้อความ" ยังต้องสร้างระบบติดตามและเตือนเองทั้งหมด
- **สรุป:** ผ่าน C1 บางส่วน แต่ setup หนักสำหรับเอกสารหลายแบบ

### 2.8 OCR ภาษาไทยเฉพาะทาง เช่น iApp Technology
- **ข้อดี:**
  - เก่งภาษาไทยมาก เช่น Thai National ID Card OCR อ้างความแม่นยำระดับตัวอักษร ~98%
  - ประมวลผล 1–2 วินาที [[iApp ID Card]](https://www.iapp.co.th/docs/ekyc/thai-national-id-card)
  - มี OCR ใบเสร็จ ทร.14/1 และเอกสารทั่วไป [[iApp Docs]](https://iapp.co.th/blog/iapp-4-new-document-ocr)
- **ข้อเสีย:**
  - เป็นโมเดลเฉพาะเอกสาร ไม่พบโมเดลสำหรับใบขับขี่ ป้ายภาษี หรือ พ.ร.บ.
  - OCR ทั่วไปให้แค่ข้อความดิบ ยังต้องเขียนกฎแยกฟิลด์เอง
  - ไม่มีระบบติดตามและเตือน
- **สรุป:** ผ่าน C2 ได้ดี แต่ไม่ผ่าน C1 (การแยกฟิลด์) และ C3

### 2.9 Vision Large Language Models (เช่น Claude, GPT, Gemini)
- **ข้อดี:**
  - อ่านภาพหรือ PDF ภาษาไทยได้ **โดยไม่ต้องเทรนหรือทำ template**
  - เข้าใจบริบท เช่น แยก "วันเกิด" กับ "วันหมดอายุ" ได้
  - ส่งผลเป็น JSON ตาม schema ได้ (structured outputs)
  - ใช้ทำ Agent ตอบคำถามด้วย tool use ได้
- **ข้อเสีย:**
  - อาจ "มั่นใจแต่ผิด" (hallucination)
  - มีค่าใช้จ่ายต่อการเรียกใช้
  - ข้อมูลส่งออกไปยังผู้ให้บริการ ต้องพิจารณา PDPA
  - คำนวณวันที่หรือแปลงปีอาจพลาด
- **สรุป:** ผ่าน C1, C2, C3 ได้ดีที่สุด ถ้า **ออกแบบกลไกป้องกันความผิดพลาด**

**ข้อสังเกต:**
- **ไม่มีโซลูชันเดียวในตลาดที่ผ่านทั้ง C1 + C2 + C3 + C4 ในราคา SME** โซลูชันที่ "เตือนเก่ง" (Fleet, CLM) ไม่อ่านเอกสารไทย
- ส่วนที่ "อ่านเก่ง" (OCR, Document AI) ก็ไม่มีระบบติดตามและเตือน

## 4. ทางเลือกที่ตอบโจทย์ และเหตุผล

**เลือก: Vision LLM เป็นตัวอ่านเอกสาร + กฎตรวจสอบ (validation) + มนุษย์ตรวจทานเมื่อไม่มั่นใจ + ระบบติดตามและเตือนที่สร้างเอง**

| เหตุผล | อธิบาย |
|-------|-------|
| ปิดช่องว่าง C1–C4 ได้ในระบบเดียว | LLM อ่านเอกสาร, ระบบเราดูแลการติดตามและการเตือน |
| ไม่ต้องเทรนต่อประเภทเอกสาร | เพิ่มเอกสารประเภทใหม่โดยแก้ prompt และ schema ไม่ต้องเก็บ dataset |
| ลดจุดอ่อนของ LLM ด้วยการออกแบบ | (1) ให้ LLM คัดลอกวันที่ดิบ แล้ว **แปลง พ.ศ.→ค.ศ. ด้วยโค้ด** (2) กฎตรวจ เช่น วันหมดอายุต้องหลังวันออก และทะเบียนรถต้องถูกรูปแบบ (3) confidence score ต่ำ → ส่งให้คนตรวจ (4) Agent ตอบจาก tool ที่ค้น DB จริง ไม่ตอบจากความจำ |
| ต้นทุนต่ำ | จ่ายตามการใช้ (~165 เอกสาร/ปี) แทนค่า license รายคันหรือรายผู้ใช้ เปลี่ยนเป็นโมเดลที่ถูกกว่าได้ใน `.env` |
| มี baseline ให้เทียบ | ระบบกฎ (regex + ข้อความ PDF) ทำงานออฟไลน์ได้ ใช้เป็น fallback และเป็นตัวเทียบในการประเมินผล |
| ทำได้ในเวลาโปรเจค | ไม่ต้องเทรนโมเดล ใช้ API + Python + SQLite |

**ข้อจำกัดที่ยอมรับ (และวิธีรับมือ):**
- **PDPA:** ส่งภาพเอกสารไปประมวลผลภายนอก
  - ใน repo สาธารณะใช้เฉพาะข้อมูลสังเคราะห์
  - ถ้าใช้งานจริง ควรขอความยินยอมพนักงาน หรือปิดเลขบัตรก่อนส่ง
  - เลือก provider ที่ไม่ใช้ข้อมูล API ไปเทรน
- **ต้องมีอินเทอร์เน็ตและ API key:** มีโหมดออฟไลน์สำรอง
